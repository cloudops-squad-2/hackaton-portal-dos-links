# Portal dos Links — Design

## Overview

Cloud-native link shortener built for the CloudOps Bootcamp Hackathon. The system consists of a NestJS/Fastify API, a React frontend, and a PostgreSQL database, all instrumented with OpenTelemetry and deployed via GitOps (ArgoCD).

## Component Design

### API

**Runtime:** Node.js 22, NestJS 12, Fastify adapter

**Module structure:**
```
src/
├── app.module.ts          Root module — imports ConfigModule (global), HealthModule, LinkModule
├── main.ts                Bootstrap with NestFastifyApplication
├── health/
│   ├── health.module.ts
│   └── health.controller.ts   GET /health → { status: 'ok' }
├── link/
│   ├── link.module.ts
│   ├── link.controller.ts     POST /api/links, GET /api/links
│   ├── redirect.controller.ts GET /:code → 302
│   ├── link.service.ts        Business logic
│   └── dto/
│       ├── create-link.dto.ts
│       └── list-links.dto.ts
└── database/
    └── prisma.service.ts      Extends PrismaClient, wired via ConfigService
```

**Request flow — create link:**
```
POST /api/links
  → LinkController.create(dto)
  → LinkService.create(dto)
      → compute expiresAt from dto.expiresIn (seconds)
      → nanoid(7) → prisma.link.create()
      → retry up to 3x on P2002 unique collision
  ← Link record
```

**Request flow — redirect:**
```
GET /:code
  → RedirectController.redirect(code)
  → LinkService.resolve(code)
      → prisma.link.findUnique({ where: { code } })
      → 404 if not found
      → 410 if expiresAt <= now
      → prisma.link.update clickCount++
  ← 302 Location: originalUrl
```

**Environment variables:**
| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | ✅ | PostgreSQL connection string |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | ✅ (prod) | OTLP collector endpoint |
| `OTEL_SERVICE_NAME` | optional | Defaults to `portal-dos-links-api` |
| `PORT` | optional | Defaults to 3000 |

### Database Schema

```prisma
model Link {
  id          String    @id @default(cuid())
  code        String    @unique
  originalUrl String
  clickCount  Int       @default(0)
  createdAt   DateTime  @default(now())
  expiresAt   DateTime?

  @@index([createdAt])
}
```

Prisma client is generated to `src/generated/prisma` — never committed.
Generated in CI by the `test-api` job (`npx prisma generate`) and during Docker build.

### CI Pipeline

```
push / PR
    │
    ├── gitleaks          secret scan (blocks all other jobs if it fails)
    │
    ├── test-api          npm ci → prisma generate → tsc → vitest run
    │
    └── build (matrix: api, frontend)
          needs: [gitleaks, test-api]
          ├── build & push image to GHCR (push events only)
          └── tag: ghcr.io/<owner>/portal-dos-links-<service>:<short-sha>
                │
                └── update-manifests (push to main/develop only)
                      needs: build
                      ├── checkout config repo (CONFIG_REPO_PAT)
                      ├── kustomize edit set image (both services)
                      └── commit + push → ArgoCD detects diff → syncs cluster
```

**Secrets required in the app repo:**
| Secret | Purpose |
|---|---|
| `GITHUB_TOKEN` | Auto-provided — GHCR login + package push |
| `CONFIG_REPO_PAT` | PAT with `repo` write scope on the config repo |

### OpenTelemetry

**API instrumentation:**
- SDK initialized before NestJS bootstrap in `main.ts`
- Auto-instrumentation: HTTP, Fastify, Prisma
- Exporter: OTLP/gRPC to the collector (`OTEL_EXPORTER_OTLP_ENDPOINT`)
- Manual spans added in `LinkService.create` and `LinkService.resolve`

**Frontend instrumentation:**
- `@opentelemetry/sdk-trace-web` + `FetchInstrumentation`
- `traceparent` propagated on every `fetch` to the API
- Exporter: OTLP/HTTP to the collector

**Trace propagation path:**
```
Browser (W3C traceparent) → API (continues span) → Prisma (child span) → PostgreSQL
```

### Docker Compose

#### Service Topology

Three services share a single bridge network `portal-net`:

```
postgres ──► api ──► frontend
```

- `postgres` — database; exposes 5432
- `api` — NestJS backend; built from `./api`; exposes 3000 (HTTP) and 4317 (OTLP/gRPC)
- `frontend` — Nginx-served React build; built from `./frontend`; exposes 80

#### Port Mapping

| Service    | Container port | Host port | Protocol | Purpose               |
|------------|---------------|-----------|----------|-----------------------|
| postgres   | 5432          | 5432      | TCP      | Database connections  |
| api        | 3000          | 3000      | TCP      | HTTP API              |
| api        | 4317          | 4317      | TCP      | OTLP/gRPC telemetry   |
| frontend   | 80            | 80        | TCP      | Web UI                |

#### Volumes

One named volume keeps Postgres data across `docker compose down`:

| Volume name     | Mount path                    | Service  |
|-----------------|-------------------------------|----------|
| `postgres_data` | `/var/lib/postgresql/data`    | postgres |

#### Build Contexts

| Service  | build.context  |
|----------|----------------|
| api      | `./api`        |
| frontend | `./frontend`   |

Both services are built from source on `docker compose up --build`, requiring no registry access (REQ-DC-01, REQ-DC-02).

#### Environment Wiring

**api**
```
DATABASE_URL=postgresql://postgres:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
OTEL_SERVICE_NAME=portal-dos-links-api
PORT=3000
```

**frontend**
```
VITE_API_URL=http://localhost:3000
```

All values are driven by variables defined in `.env` (see `.env.example` below), so no credentials are hardcoded in the compose file (REQ-NF-02, REQ-DC-07).

#### Startup Ordering

```
postgres (healthy) ──condition: service_healthy──► api (started) ──condition: service_started──► frontend
```

- `api.depends_on.postgres.condition: service_healthy` — the API only starts after Postgres passes its healthcheck (REQ-DC-08, REQ-DC-09).
- `frontend.depends_on.api.condition: service_started` — the frontend starts once the API container is running (REQ-DC-08).

#### Postgres Healthcheck

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER}"]
  interval: 5s
  timeout: 5s
  retries: 5
```

Uses `$$` escaping so Docker Compose expands the variable at container runtime rather than at compose-file parse time (REQ-DC-09).

#### `.env.example` (repo root)

Documents every variable referenced by `docker-compose.yml`:

```dotenv
# PostgreSQL credentials — used by the postgres service and interpolated into DATABASE_URL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=changeme
POSTGRES_DB=portal_dos_links

# Frontend — base URL of the API reachable from the browser
VITE_API_URL=http://localhost:3000

# OpenTelemetry — logical service name shown in traces
OTEL_SERVICE_NAME=portal-dos-links-api
```

Operators copy this file to `.env` and fill in real values before running `docker compose up` (REQ-DC-10).
