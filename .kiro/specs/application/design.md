# Portal dos Links — Design

## Architecture Overview

```
Browser
  │
  ├── Frontend (React/Next.js)
  │     └── OpenTelemetry Browser SDK (W3C traceparent header)
  │
  └── GET /:code ──────────────────────────────────────────┐
                                                           ▼
                                               API (NestJS + Fastify)
                                                 │   ├── LinkModule
                                                 │   │     ├── LinkController     POST /api/links
                                                 │   │     │                      GET  /api/links
                                                 │   │     ├── RedirectController GET  /:code
                                                 │   │     └── LinkService
                                                 │   ├── HealthModule             GET  /health
                                                 │   ├── DatabaseModule
                                                 │   │     └── PrismaService
                                                 │   └── OpenTelemetry SDK (OTLP exporter)
                                                 │
                                                 └── PostgreSQL
                                                       └── Prisma 7 + adapter-pg
```

## Component Design

### API

**Runtime:** Node.js 22, NestJS 12, Fastify adapter

**Module structure:**
```
src/
├── app.module.ts          Root module — imports ConfigModule (global), HealthModule, LinkModule
├── main.ts                Bootstrap with NestFastifyApplication
├── health/
│   ├── health.module.ts
│   └── health.controller.ts   GET /health → { status: 'ok' }
├── link/
│   ├── link.module.ts
│   ├── link.controller.ts     POST /api/links, GET /api/links
│   ├── redirect.controller.ts GET /:code → 302
│   ├── link.service.ts        Business logic
│   └── dto/
│       ├── create-link.dto.ts
│       └── list-links.dto.ts
└── database/
    └── prisma.service.ts      Extends PrismaClient, wired via ConfigService
```

**Request flow — create link:**
```
POST /api/links
  → LinkController.create(dto)
  → LinkService.create(dto)
      → compute expiresAt from dto.expiresIn (seconds)
      → nanoid(7) → prisma.link.create()
      → retry up to 3x on P2002 unique collision
  ← Link record
```

**Request flow — redirect:**
```
GET /:code
  → RedirectController.redirect(code)
  → LinkService.resolve(code)
      → prisma.link.findUnique({ where: { code } })
      → 404 if not found
      → 410 if expiresAt <= now
      → prisma.link.update clickCount++
  ← 302 Location: originalUrl
```

**Environment variables:**
| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | ✅ | PostgreSQL connection string |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | ✅ (prod) | OTLP collector endpoint |
| `OTEL_SERVICE_NAME` | optional | Defaults to `portal-dos-links-api` |
| `PORT` | optional | Defaults to 3000 |

### Database Schema

```prisma
model Link {
  id          String    @id @default(cuid())
  code        String    @unique
  originalUrl String
  clickCount  Int       @default(0)
  createdAt   DateTime  @default(now())
  expiresAt   DateTime?

  @@index([createdAt])
}
```

Prisma client is generated to `src/generated/prisma` — never committed.
Generated in CI by the `test-api` job (`npx prisma generate`) and during Docker build.

### CI Pipeline

```
push / PR
    │
    ├── gitleaks          secret scan (blocks all other jobs if it fails)
    │
    ├── test-api          npm ci → prisma generate → tsc → vitest run
    │
    └── build (matrix: api, frontend)
          needs: [gitleaks, test-api]
          ├── build & push image to GHCR (push events only)
          └── tag: ghcr.io/<owner>/portal-dos-links-<service>:<short-sha>
                │
                └── update-manifests (push to main/develop only)
                      needs: build
                      ├── checkout config repo (CONFIG_REPO_PAT)
                      ├── kustomize edit set image (both services)
                      └── commit + push → ArgoCD detects diff → syncs cluster
```

**Secrets required in the app repo:**
| Secret | Purpose |
|---|---|
| `GITHUB_TOKEN` | Auto-provided — GHCR login + package push |
| `CONFIG_REPO_PAT` | PAT with `repo` write scope on the config repo |

### OpenTelemetry

**API instrumentation:**
- SDK initialized before NestJS bootstrap in `main.ts`
- Auto-instrumentation: HTTP, Fastify, Prisma
- Exporter: OTLP/gRPC to the collector (`OTEL_EXPORTER_OTLP_ENDPOINT`)
- Manual spans added in `LinkService.create` and `LinkService.resolve`

**Frontend instrumentation:**
- `@opentelemetry/sdk-trace-web` + `FetchInstrumentation`
- `traceparent` propagated on every `fetch` to the API
- Exporter: OTLP/HTTP to the collector

**Trace propagation path:**
```
Browser (W3C traceparent) → API (continues span) → Prisma (child span) → PostgreSQL
```

### Docker

**API Dockerfile (multi-stage):**
```
Stage 1 — build
  FROM node:22-alpine
  npm ci
  npx prisma generate
  npm run build
  npm prune --omit=dev

Stage 2 — prod
  FROM node:22-alpine
  COPY --from=build dist, node_modules, package.json
  USER node
  EXPOSE 3000
  CMD ["node", "dist/main.js"]
```

**Frontend Dockerfile (multi-stage):**
```
Stage 1 — build
  FROM node:22-alpine
  npm ci
  npm run build        (outputs to /app/dist)

Stage 2 — prod
  FROM nginx:alpine
  COPY --from=build /app/dist /usr/share/nginx/html
  EXPOSE 80
```
